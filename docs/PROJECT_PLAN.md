# PageVoice2 项目计划

## 1. 项目目标

开发一款手机和 iPad 优先的纯静态 PWA：

- 拍摄或选择英文书页照片
- 在浏览器本地完成 OCR
- 校对识别结果
- 逐句朗读并高亮当前句
- 点击句子跳转朗读
- 点击单词查看中文释义和发音
- 本地保存阅读项目与进度
- 缓存后支持离线使用
- 部署到 GitHub Pages
- 不上传书页照片，不要求登录或后端服务器

正式支持基线：

- iOS/iPadOS 17+
- Android Chrome 当前主流版本
- 桌面 Safari、Chrome、Edge 当前主流版本

## 2. 优先级定义

| 优先级 | 含义 | 发布规则 |
|---|---|---|
| P0 | MVP 核心功能或关键技术风险 | 未完成不能发布 |
| P1 | 明显改善可靠性和使用体验 | 尽量随 MVP 发布，必要时可延后一个小版本 |
| P2 | 后续增强功能 | 不进入第一版开发 |
| P3 | 远期能力 | 仅保留扩展方向 |

## 4. 里程碑

### M0：关键技术验证

目标：先确认 Safari 朗读与移动端 OCR 可达到 MVP 要求。

- 建立最小 Web Speech 验证能力。
- 真机检查 voice 加载、逐句队列、暂停恢复、跳句和语速。
- 测试切后台、锁屏、其他音频打断后的恢复。
- 使用真实英文书页测试 OCR 时间、准确率和内存。
- 完成条件：Safari 可连续朗读并从中断恢复；单张清晰书页可在设备本地完成 OCR。

### M1：工程骨架和本地项目

目标：建立可持续开发的数据和页面基础。

- 初始化 React、TypeScript、Vite 和测试环境。
- 建立移动优先布局、Hash 路由和错误处理。
- 实现项目创建、列表、继续阅读和 IndexedDB。
- 定义项目、句子、播放状态和设置的数据类型。
- 完成条件：可以创建项目、保存测试正文并在刷新后恢复。

### M2：拍照、OCR 和校对

目标：打通“照片到可编辑正文”的完整路径。

- 拍照、相册选图、预览和旋转。
- 图片缩放与基础增强。
- Tesseract.js Worker、进度、取消和错误处理。
- OCR 正文编辑、保存和压缩缩略图。
- 完成条件：真实书页可从选图完成到正文保存；原图不写入项目存储。

### M3：逐句阅读引擎

目标：完成产品的核心阅读体验。

- 分句与朗读状态机。
- 当前句高亮和自动连续播放。
- 点击句子、上一句、下一句、暂停和继续。
- 单句重复、三档语速和 voice 选择。
- Safari 中断恢复。
- 完成条件：所有控制不会重叠发声，高亮和声音一致，刷新后恢复进度。

### M4：词典和移动端体验

目标：完成点词学习与正式响应式界面。

- 构建约 5 万词核心离线词典及前缀分片。
- 实现词形还原、中文释义、音标和单词发音。
- 完成手机底部释义面板和 iPad 侧栏。
- 完成长正文自动滚动和触控细节。
- 完成条件：常见原版书词汇可离线查询，单词发音不破坏正文进度。

### M5：PWA、离线与发布

目标：形成可安装、可离线、可公开访问的 MVP。

- Manifest、图标、Service Worker 和版本管理。
- 缓存应用外壳、OCR 模型和核心词典。
- 离线准备进度、失败重试和更新提示。
- 存储容量检查与持久化请求。
- GitHub Actions 构建和 GitHub Pages 发布。
- 完成条件：准备完成后断网仍能启动、OCR、朗读和查词，项目子路径资源正常。

## 5. 发布范围

第一版必须完成全部 P0，并尽量完成以下 P1：

- 项目删除和重命名
- 压缩缩略图
- 英文 voice 选择
- 音标显示
- 自动滚动当前句
- 存储持久化请求
- 新版本更新提示

明确推迟：

- 音频下载
- 在线词典和 AI 翻译
- 云同步与登录
- 多页批量 OCR
- 复杂透视矫正
- 逐词同步高亮
- 项目备份导入导出

## 6. 测试原则

- 每个里程碑运行与本次功能直接相关的最小测试。
- 朗读状态机、分句、词形还原和数据升级使用自动化单元测试。
- OCR、PWA 和 IndexedDB 使用浏览器集成测试。
- Safari 朗读、拍照入口、切后台和安装 PWA 必须真机测试。
- M5 发布前执行一次完整回归。
- 不以 Chrome 模拟移动设备代替 iPhone/iPad Safari 真机验收。

## 7. 假设与约束

- 使用 React + TypeScript + Vite。
- 正式支持 iOS/iPadOS 17+。
- 核心词典约 5 万词，按前缀拆分。
- OCR 后只保存压缩缩略图和校对正文。
- 项目使用 Hash 路由，避免 GitHub Pages 刷新路径产生 404。
- MVP 不建立后端，也不发送书页照片或正文。
- GitHub remote 使用 SSH；部署阶段需要提供 GitHub 用户名和目标仓库。
- 浏览器 TTS 不承诺生成可下载音频文件。
- 浏览器本地存储可能被系统清理，MVP 提示风险，项目导入导出排入后续版本。
